# 17033: Copilot Studio did not report a successful publish

[All error codes](../ErrorCodes.md)

## What happened

`msagent agent deploy --publish` asked Copilot Studio to publish the agent but did not see the publish succeed. The deploy was recorded before the publish was requested.

When the message names a status other than `Succeeded`, Copilot Studio finished the publish without making the content live, so the pushed content is saved as a draft. When the message says the publish's progress could not be read, it gives the reason without echoing the service's response; the publish may have finished, so check the agent's publish state.

## Why this happens

A publish succeeds only when Copilot Studio reports that the new publish operation finished `Succeeded`. Any other status, such as `Failed`, means the publish did not make the content live. When the agent's publish status cannot be read, for example because the service refused the request, the command cannot tell whether the publish succeeded.

## How to fix it

For a reported status, open the agent in Copilot Studio to see why the publish failed, fix the content or permissions it names, and run the deploy again. When the progress could not be read, check the agent's publish state in Copilot Studio, then run the deploy again to confirm the publish finished.

## How to avoid it

Resolve draft validation issues and verify publishing permissions in the target environment before deploying with `--publish`.
