# 17033: The service refused a component that already exists

[All error codes](../ErrorCodes.md)

## What happened

The component push could not complete because the service reported that a component the push creates already exists in the destination, even after the baseline was reread. The message names the component when the service identified it.

## Why this happens

The requested creation conflicts with a component the destination already holds, and the service and the workspace's synchronization state still disagree about it. The component may have been added outside this workspace, for example in Copilot Studio.

## How to fix it

- Run `msagent agent pull` to bring the cloud copy into the workspace, review it against your local changes, then deploy again.
- If your local component is meant to be a separate one, rename it, then deploy again.

The agent definition was left as it was by the incomplete component push, but earlier connector, workflow, prompt, or reference operations may already have changed cloud state.

## How to avoid it

Pull before deploying when the agent may have changed in Copilot Studio, and keep component names distinct.
