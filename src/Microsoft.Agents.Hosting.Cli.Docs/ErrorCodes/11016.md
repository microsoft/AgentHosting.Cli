# 11016: Pull would discard local workflow changes

[All error codes](../ErrorCodes.md)

## What happened

The workflow folder contains local changes that have not reached the environment, and pulling would replace them.

## Why this happens

The downloaded workflow differs from your current local working copy. Without an explicit overwrite decision, the CLI protects that unpublished work.

## How to fix it

If the local changes should be kept in the environment, run `msagent agent deploy` for the intended deployment, then pull if still needed.

If you intentionally want the cloud copy instead, back up or commit any edits you might need, then repeat the pull with `--overwrite`. That option discards the protected local changes; it is not a merge.

Do not use overwrite until you have confirmed the workflow and environment are correct.

## How to avoid it

Keep workflow edits versioned and coordinate cloud and local authoring. Review pending changes before downloading replacements.
