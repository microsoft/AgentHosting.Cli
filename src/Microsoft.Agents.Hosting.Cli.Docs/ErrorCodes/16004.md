# 16004: Existing resource conflicts with provisioning

[All error codes](../ErrorCodes.md)

## What happened

Provisioning found an existing bot or application that cannot be safely reconciled with the request.

## Why this happens

ABS apply refuses destructive changes to an existing bot's application ID or identity type. Identity creation can also find multiple applications with the same display name, or an App Registration whose sign-in audience is incompatible with the requested configuration.

## How to fix it

For ABS, verify the bot and supplied application ID, then use compatible inputs or a distinct bot name. Rerun `msagent abs preview` before applying. Its current supplied-app path does not resolve this conflict through `--app-object-id`.

For ordinary App Registration ambiguity, select the intended application with `--app-id` or `--object-id`. Blueprint creation instead needs an unambiguous display name. Have the application owner assess sign-in-audience changes; do not convert an unrelated application blindly.

Do not delete duplicate applications or rebind a production bot merely to clear the error.

## How to avoid it

Use explicit identities and review existing resources before reconciliation. ABS and identity commands are feature-gated.
