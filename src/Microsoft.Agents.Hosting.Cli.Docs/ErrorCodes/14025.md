# 14025: AMS request redirect was rejected

[All error codes](../ErrorCodes.md)

## What happened

An AMS request received an HTTP redirect. The CLI did not follow it or resend your delegated authorization header to the redirect destination.

## Why this happens

The configured data-plane or control-plane endpoint may point to a redirecting front door, outdated address, or incorrectly configured service route. This guard applies to agent reads, package uploads, and deployment creation.

## How to fix it

Ask the service owner to verify the configured endpoint and remove the unexpected redirect from the supported request path. Do not manually replay the credential to the redirect URL, or copy that URL into configuration without verifying its ownership.

Check the phase in the error. If an upload or deployment creation request was sent, inspect remote state before retrying; a redirect response alone is not proof that nothing was stored. For an agent read, no later mutation has begun.

## How to avoid it

Use the approved direct HTTPS service endpoint and keep proxy routing consistent with the service contract.
