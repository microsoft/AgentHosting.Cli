# 11033: Reference removed but connection deletion did not finish

[All error codes](../ErrorCodes.md)

## What happened

The connection reference was removed successfully, but deleting the underlying connection failed or timed out.

## Why this happens

Reference removal and connection deletion are separate steps. A later service rejection or timeout does not restore the removed reference. For a timeout, the connection's deletion outcome may be unknown.

## How to fix it

Do not pass `--connection-reference` again: that reference is already gone.

Resolve the reported permission, dependency, or service issue, then run the connection-only removal command printed in the remediation. It carries the connector and connection identifiers needed after the reference has disappeared.

Deleting an already absent connection succeeds, so that retry is appropriate even when a timeout left the outcome uncertain. Verify that the connection is still intended for deletion and not needed by other consumers.

## How to avoid it

Check connection ownership and external dependencies before combined removal, and retain the operation's recovery command when a later step fails.
