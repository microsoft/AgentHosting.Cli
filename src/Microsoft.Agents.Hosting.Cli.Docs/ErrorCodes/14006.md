# 14006: Deployment record conflicts with an existing record

[All error codes](../ErrorCodes.md)

## What happened

Creating or updating a deployment record would violate a uniqueness rule. The conflicting record was not written.

## Why this happens

Within an agent, deployment names are compared case-insensitively. MCS agents also cannot have two deployment records for the same target environment, even if the records have different names or stages. The message identifies the conflicting constraint and value.

## How to fix it

Inspect `msagent deployment list` for the selected agent. Reuse the existing deployment if it already represents the destination you want.

For a name collision, choose a genuinely different name. For an environment collision, changing only the name or stage will not help: use the existing record or select a different environment. An MCS deployment update can rename a record, but cannot change its environment or stage.

## How to avoid it

List deployments before creating another one. Treat the environment as the MCS deployment's destination, not as a reusable label.
