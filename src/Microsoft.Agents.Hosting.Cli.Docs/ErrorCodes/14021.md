# 14021: AMS response does not match the request

[All error codes](../ErrorCodes.md)

## What happened

The CLI received a response but could not confirm that it describes the requested agent, uploaded bytes, or newly created deployment.

## Why this happens

Checks compare agent identity with the selected tenant and environment, package digest and size with local bytes, and deployment properties with the requested revision and destination. Deployment checks also reject unexpected runtime, custom-endpoint, or quarantine state. The message identifies the phase and mismatched field.

## How to fix it

Do not treat the response as success. If the phase was an agent read, correct the selected environment or service routing before continuing. If it was upload or deployment creation, remote state may already exist.

Use any client and service request IDs to have the service owner inspect authoritative state before retrying. Do not deploy an unverified revision or create another deployment simply to get a successful response.

## How to avoid it

Keep agent, environment, and service endpoint configuration aligned. Preserve correlation IDs when reporting a mismatch; do not include tokens or package contents.
