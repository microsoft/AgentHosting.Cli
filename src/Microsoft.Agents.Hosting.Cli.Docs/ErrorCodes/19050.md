# 19050: Dev's edits and a later commit changed the same lines

[All error codes](../ErrorCodes.md)

## What happened

`msagent agent capture`, or a remote deploy to the Dev deployment of an MCS agent, found that the edits made in Dev's Copilot Studio agent and a later commit to the repository changed the same lines. A capture reports `Nothing was captured: Dev's edits and commit <commit> changed the same lines in <paths>.`, and a Dev deploy reports `Nothing was deployed or captured: Dev's edits and commit <commit> changed the same lines in <paths>.` The commit is the one the merge ran against, and the paths are the files the service reports.

## Why this happens

A capture merges Dev's edits since its last deploy or capture with the changes later commits made to the agent's folder. Changes to different lines or files merge into one new commit; changes to the same lines can't merge until you choose a side. A remote deploy to Dev captures Dev's edits before it replaces them, so it stops the same way.

## How to fix it

Choose the way that gives the outcome you want. After a capture:

- Keep Dev's lines: capture again with `msagent agent capture --resolve cloud`; the other changes of both sides merge as usual.
- Drop Dev's edits: deploy the latest commit to Dev with `msagent agent deploy --remote --deployment-name <dev-deployment> --overwrite`, which first saves Dev's edits on its snapshot branch.

After a Dev deploy, the error names the commit you deployed:

- Keep Dev's lines: capture with `--resolve cloud`, then deploy again; the other changes of both sides merge as usual.
- Drop Dev's edits: deploy that commit with `--overwrite`, which first saves Dev's edits on its snapshot branch.

To combine both sides, capture with `--resolve cloud`, run `git pull` in your clone, edit those files, then commit and push.

## How to avoid it

Capture edits made in Copilot Studio soon after you make them, and deploy new commits to Dev before you edit there, so both sides build on the same commit.
