# 99005: Internal authentication context is missing or inconsistent

[All error codes](../ErrorCodes.md)

## What happened

The operation could not continue with a safely bound authentication context.
This is an internal failure, with exit code 1 and error kind
`authentication-context-invalid`, not a token-claim rejection.

## Why this happens

A resource request or product-principal lookup has no captured authentication
context, a token provider or validated resource token is bound to a different
context or target tenant, or the required resource-token provider is not configured.

Actual token principal-mode mismatches use [12017](12017.md). Missing or invalid
token directory object IDs use [12018](12018.md).

## How to fix it

For `msagent`, report the command, CLI version, error code, and redacted message
to the CLI issue tracker. Do not include tokens, credentials, or private project
contents. Signing in again, changing accounts, or clearing profiles is not the
recommended remedy for an internal context failure.

For an application embedding Core, supply the captured authentication context
for the operation and configure the required token provider. Ensure the request,
provider, and returned validated resource token refer to the same captured
context and target tenant. Do not substitute the current active profile or
fall back to an unvalidated identity.

If the larger command could already have changed remote or local state, inspect
the intended target before retrying; this error does not guarantee rollback.

## How to avoid it

Keep one immutable authentication context throughout each operation and preserve
its explicit profile and tenant binding across resource consumers. Cover custom
Core composition and context propagation with offline tests.
