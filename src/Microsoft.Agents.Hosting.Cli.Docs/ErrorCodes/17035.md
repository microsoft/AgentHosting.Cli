# 17035: Locally edited knowledge files the environment deleted or replaced can't be kept

[All error codes](../ErrorCodes.md)

## What happened

The pull stopped before it changed the workspace. The environment deleted or replaced knowledge files that were changed locally, and the pull can't keep them. The message names each file.

## Why this happens

When the environment deletes a knowledge file that was changed locally, in its `.mcs.yml` metadata or in its content since its last sync, a pull normally keeps the file as a new local file for the next deploy to create again. It can't do that when:

- the file's content was never downloaded, so the workspace holds only its metadata;
- the environment deleted the agent or skill that the file belongs to; or
- the environment added a knowledge file with the same name in its place.

The last two also apply to a knowledge file you added locally that the environment doesn't have yet.

Rather than delete local changes without asking, the pull stops.

## How to fix it

- To accept the environment's changes, re-run `msagent agent pull` with `--overwrite`. The pull deletes the named files and their `.mcs.yml` metadata, then applies the latest changes. Copy anything you want to keep out of the workspace first. When the environment added a file with the same name, you can then apply your change to that file.
- Or undo your local changes to the named files and pull again. To keep a file you added, rename it, or move it out of the agent or skill the environment deleted, before you pull.

## How to avoid it

Pull before you edit knowledge files, and coordinate with other authors before you delete or replace knowledge files in the environment.
