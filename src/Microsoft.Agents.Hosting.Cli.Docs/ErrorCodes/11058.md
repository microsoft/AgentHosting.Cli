# 11058: Agent record has no environment

[All error codes](../ErrorCodes.md)

## What happened

The command needed the environment an agent belongs to, but the agent's record in the project's `agent.config.json` has no `environmentId`. The error names the agent and the configuration file.

## Why this happens

Commands that act on an agent in the cloud use the environment named by the selected deployment, and otherwise the agent's home environment from its record. Here the record names no environment, and no selected deployment named one either. The CLI records an environment when it registers an agent, so the value may have been removed or lost when the configuration was edited, merged, or restored.

## How to fix it

- Preserve the current configuration file before changing it. It may hold the only copy of the project's deployment records.
- Set the agent record's `environmentId` in `.config\agent.config.json` to the environment the agent belongs to. `msagent env list` lists the environments available to the signed-in account.
- If the value was lost in a merge or restore, you can instead restore a known-good version from source control, keeping any newer agent or deployment records.
- Run the command again.

## How to avoid it

Let CLI commands write agent records, and review configuration merges so every agent record keeps its `environmentId`.
