# 14026: Deployment update redirect was rejected

[All error codes](../ErrorCodes.md)

## What happened

The deployment package-update path received an HTTP redirect. The CLI refused to follow it with your credentials.

## Why this happens

The initial deployment read or the subsequent update reached a route that redirects instead of returning the expected AMS response. The error includes the phase, configured host, correlation information, and whether an update was attempted.

## How to fix it

Have the service owner verify the control-plane endpoint and routing. Do not send a token directly to the redirect destination.

If the message says **No update request was sent**, correct the endpoint before repeating the update. If the outcome may be indeterminate, inspect authoritative deployment state using the request IDs before deciding whether to repeat it. The revision might already have changed.

This is a deployment update problem, not a request to re-upload package bytes.

## How to avoid it

Use the approved non-redirecting HTTPS service endpoint. Check service routing when changing proxies, front doors, or deployment configuration.
