# 16010: Provisioning output was blocked to protect secrets

[All error codes](../ErrorCodes.md)

## What happened

The CLI detected possible credential material in an ABS report or connection metadata and refused to emit or persist that payload.

## Why this happens

ABS scaffolding output is designed to contain identifiers and references, not secrets. The safety check rejects credential-named values and token-like or private-key material. The error lists affected property paths, not their contents. This can indicate an integration defect or sensitive-looking data placed in a field intended for ordinary metadata.

## How to fix it

Do not bypass the check or paste the rejected payload into logs or support tickets. Report the CLI version, operation, and safe property paths so the issue can be investigated.

Inspect Azure resource state before retrying: the bot write can finish before metadata persistence or report generation fails. Do not create another bot merely because output was blocked.

If credentials were independently exposed elsewhere, follow your organization's incident and rotation process.

## How to avoid it

Keep secrets out of resource names, descriptions, and connection metadata. Use approved secret storage and references instead.
