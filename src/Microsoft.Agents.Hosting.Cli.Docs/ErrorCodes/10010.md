# 10010: Workspace destination already contains content

[All error codes](../ErrorCodes.md)

## What happened

Creation or cloning refused to write into a workspace destination that already contains content.

## Why this happens

The agent name and project path resolve to an existing folder that is not empty: it may hold a workflow, an agent project, or unrelated files. The CLI will not overwrite that content or mix new files into it as part of creating a new workspace.

## How to fix it

Choose a different `--agent-name` or a `--project` directory that does not contain the conflicting workspace folder.

If the existing folder is the agent you meant to use, inspect it and use its existing registration instead of creating another one. If it is a partial earlier attempt, preserve and inspect its files before deciding how to recover; do not clear a directory just because creation refused it.

## How to avoid it

Use distinct destinations for new agents and clones. Check the resulting workspace folder before starting creation.
