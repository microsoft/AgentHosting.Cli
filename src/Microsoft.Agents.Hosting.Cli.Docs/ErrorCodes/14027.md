# 14027: AMS request timed out

[All error codes](../ErrorCodes.md)

## What happened

An AMS request (an agent or deployment read, list, or change) exceeded the request timeout before its response was fully received.

## Why this happens

The AMS adapter allows two minutes for a request and its response handling. Slow service processing, an unavailable endpoint, or a stalled network connection can exhaust that time. The error identifies the phase and includes a client request ID.

## How to fix it

If this was a read or a list, confirm service reachability and retry once the service is responsive. Nothing changed in that phase.

If the message says the remote outcome may be indeterminate (a create, update, deploy, or delete), do not blindly repeat it. Check the current state with `msagent agent show` or `msagent deployment show` first, and have the service owner correlate the request ID if it stays unclear. A timeout does not prove the service rejected or rolled back the request.

Keep the intended agent, commit, and deployment unchanged during investigation; do not create a new name merely to bypass uncertainty.

## How to avoid it

Check service health and network access before deployment, and preserve correlation IDs for timed-out mutations.
