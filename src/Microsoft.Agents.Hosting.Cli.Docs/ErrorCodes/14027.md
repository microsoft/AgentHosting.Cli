# 14027: AMS request timed out

[All error codes](../ErrorCodes.md)

## What happened

An agent-read or deployment-creation request exceeded the request timeout before its response was fully received.

## Why this happens

The AMS adapter allows two minutes for a request and its response handling. Slow service processing, an unavailable endpoint, or a stalled network connection can exhaust that time. The error identifies the phase and includes a client request ID.

In AMS mode, the requests msagent sends for MCS agents and standalone workflows report this error too. An agent register, `msagent agent deploy --remote` and `msagent agent capture` send a request whose answer is lost once more before they report it, a deploy or capture with the same idempotency key and a register with the same agent id, so the answer to that second request was lost too. The message then names both requests: `clientRequestId=<first>, replayClientRequestId=<second>`.

## How to fix it

If this was an agent read, confirm service reachability and retry once the service is responsive. No deployment creation has started in that phase.

If the message says the remote outcome may be indeterminate, do not blindly repeat deployment creation. Have the service owner inspect state and correlate the request ID first. A timeout does not prove the service rejected or rolled back the request.

Keep the intended agent, revision, and destination unchanged during investigation; do not create a new name merely to bypass uncertainty.

## How to avoid it

Check service health and network access before deployment, and preserve correlation IDs for timed-out mutations.
