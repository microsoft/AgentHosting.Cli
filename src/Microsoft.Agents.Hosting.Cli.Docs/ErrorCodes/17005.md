# 17005: The sharing recipient matches multiple accounts

[All error codes](../ErrorCodes.md)

## What happened

The sharing recipient selector matched more than one account in the environment. The CLI could not choose a unique recipient.

## Why this happens

Display names and other human-readable account identifiers are not necessarily unique. Granting access to an arbitrary match would be unsafe.

## How to fix it

Review the matches printed with the error. Obtain the intended recipient's Entra object ID from an administrator or trusted directory source, then repeat the sharing operation using that ID in the recipient selector.

Verify the object belongs to the intended principal in the destination tenant, especially for guest accounts. Do not simply choose the first matching name or grant access to every match.

## How to avoid it

Use stable, tenant-correct object IDs in access-management automation. Confirm recipient identity before changing permissions instead of relying on display names alone.
