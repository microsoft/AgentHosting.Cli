# 12007: Sign-in or consent needs interaction

[All error codes](../ErrorCodes.md)

## What happened

The requested authentication, selection or renewal requires interaction that this invocation
does not allow. This code is always **exit 3**, including the pre-acquisition non-interactive gate.

## Why this happens

Explicit interactive create/login (including device code) with `--non-interactive=true` is rejected
before client/cache enumeration even if a cached account exists. Selector-free select requires a
picker. A private user session may require consent/renewal, or a pinned AzureCLI/PowerShell/azd
source may be forbidden in NI before its constructor/process runs.
The profile's exact account may also be absent from its private or broker-backed cache;
the CLI does not fall back to another operating-system account.

## How to fix it

For an interactive workflow, omit `--non-interactive=true` and complete the approved sign-in/consent.
For select, supply exactly one `--index` or `--name` to avoid the picker. For automation, explicitly
configure an eligible workload/ROPC method rather than expecting cached login or device code to
bypass the gate. Do not silently change a persisted developer-source pin to another identity.

Follow the resource-specific remediation printed with the error; repeated non-interactive retries cannot satisfy an interactive requirement.
If the selected profile account is no longer available, run `msagent auth create` for the
intended identity and cloud before retrying.

## How to avoid it

Choose a supported automation credential and obtain required permissions before unattended work.
`--json` alone does not prohibit interaction; a stored profile does not guarantee silent renewal.
