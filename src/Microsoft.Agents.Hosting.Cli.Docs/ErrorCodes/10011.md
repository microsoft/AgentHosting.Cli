# 10011: Local project is not connected to Copilot Studio

[All error codes](../ErrorCodes.md)

## What happened

The CLI found local project content, but no Copilot Studio workspace connection to pull from.

## Why this happens

A local project can exist before it has been deployed and connected. Restored or copied files may also lack their original connection state. Pulling requires a known remote source; local files alone do not establish one.

With AMS mode on, `msagent agent init`, a git clone, and `msagent agent deploy --remote` to Test or Prod write no connection, and a remote deploy to Dev writes one only when the folder holds exactly the deployed commit: a folder you restored or cloned is connected by a deploy to Dev from the folder, or by a remote deploy to Dev of the commit it holds.

## How to fix it

If these files should create the agent, select the intended deployment and run `msagent agent deploy` to create and connect it.

If you instead want an existing cloud agent's content, use `msagent agent create --agent-type MCSAgent --mcs-clone-agent-id <cloud-agent-id> --environment-id <environment-id> --project <empty-directory>` to download and register it in a separate project. Preserve the current files so the recovery does not replace unpublished work. `agent pull` only updates an already connected, registered workspace.

With AMS mode on, for an agent AMS registered: to bring Copilot Studio changes into the repository, run `msagent agent capture`, then `git pull`. To connect this folder, deploy it to Dev: `msagent agent deploy` deploys the folder, and `msagent agent deploy --remote` connects it when the folder holds exactly the commit it deploys.

Do not manufacture connection state by editing hidden workspace files.

## How to avoid it

Distinguish local scaffolding from a connected workspace. Keep backups of local edits before downloading cloud content into a new working copy.
