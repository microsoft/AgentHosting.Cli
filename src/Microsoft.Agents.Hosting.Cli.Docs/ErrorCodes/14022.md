# 14022: Deployment update response identity mismatch

[All error codes](../ErrorCodes.md)

## What happened

The package-revision update could not confirm that the service response belongs to the selected deployment and requested revision.

## Why this happens

The CLI first reads the deployment and checks tenant, home environment, agent, and deployment identity. After updating, it checks those identities again and verifies the selected Package Revision. A mismatch can therefore occur before or after an update request.

## How to fix it

Read the outcome statement carefully. **No update request was sent** means the initial read failed identity checks: verify your selected environment, agent, deployment, and configured service.

If the message says the outcome may be indeterminate, an update was attempted. Ask the service owner to inspect authoritative deployment state using the request IDs before retrying. Do not assume the old revision remains selected or upload a new package as a workaround.

## How to avoid it

Keep identifiers from the same agent and home environment together. Package-revision updates require `AmsFeatures`; they select an existing revision rather than uploading bytes.
