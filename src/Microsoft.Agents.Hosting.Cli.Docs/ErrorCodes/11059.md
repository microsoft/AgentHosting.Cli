# 11059: Copy could not be prepared

[All error codes](../ErrorCodes.md)

## What happened

`msagent agent copy` stopped before creating the copy. Preparing it, or checking it against the source's environment, produced the findings listed in the error. Nothing was written and nothing was sent to Copilot Studio.

## Why this happens

A copy must own new identities for itself and for everything it copies, without changing its source. Copying stops when the source holds something the copy could not own safely, or when the environment check finds a conflict, such as an identity the copy would use that is already taken. For example, a custom connector can be copied only when the environment derives its internal identifier from its name prefix and display name.

A standalone workflow copy also stops when its source does not hold exactly one complete cloud flow, when its `metadata.yml` writes the flow's name or state in a form the copy cannot rewrite, such as a YAML block scalar, or when the copy's name is the source flow's own name or the name of another flow in the environment. Any copy also stops when a `workflow.json` it copies holds comments or trailing commas, because a deploy reads it as strict JSON.

## How to fix it

- Read each finding in the error.
- Resolve the findings in the source. For an agent, choose another `--schema-name` when a finding concerns the copy's schema name. For a workflow, choose another `--agent-name` when a finding names a flow that already has the copy's name.
- When a finding ends "Copy the workflow again.", a new copy is enough: it draws new identities.
- Run `msagent agent copy` again. Because nothing was written, retrying is safe.

## How to avoid it

Keep each custom connector's internal identifier the one the environment derives from its name prefix and display name, and copy from a workspace connected to the environment the copy deploys to. Give a workflow copy a name no other flow in the environment has.
