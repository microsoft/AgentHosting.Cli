# 17026: A refused workflow or prompt blocked component deployment

[All error codes](../ErrorCodes.md)

## What happened

A component push failed after the service had already refused a workflow or AI prompt on which the components depend.

## Why this happens

Workflows and prompts are sent before agent components. If the service does not store one, a later component cannot resolve its dependency. An unbound connection reference is a common cause.

## How to fix it

Read the earlier refusal warnings, not just the final push error. Inspect `msagent deployment connection list`; use `msagent deployment connection update` with the appropriate selectors to bind a required reference. Resolve other refusal reasons as reported.

Inspect what the cloud accepted before deploying again. This sequence is not atomic: some auxiliary resources may already be updated, and retrying can overwrite workflows, prompts, or connectors by design.

## How to avoid it

Verify connection bindings and dependency readiness before deployment. Treat warnings about refused resources as incomplete work even when other upload steps succeeded.
