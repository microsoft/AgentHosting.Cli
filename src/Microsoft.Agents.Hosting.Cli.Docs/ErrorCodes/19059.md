# 19059: git tracks a .mcs folder, or commits msagent would push hold one

[All error codes](../ErrorCodes.md)

## What happened

With AMS mode on, `msagent agent create` or `msagent agent init` was refused because a `.mcs` folder
would have reached the GRS repository. The message names the folders and says which case it is:

- **git tracks a .mcs folder** inside a folder the command commits or restores. The command stopped
  before it asked anything, and nothing was changed.
- **Commits msagent would push hold a .mcs folder.** These are all the commits of a folder that
  msagent links to a new repository, or the commits of a clone that `origin` doesn't have yet. A
  commit that only deletes `.mcs` doesn't count. The command stopped before it asked anything, and
  nothing was changed.
- **git tracks a .mcs folder** inside a folder that `msagent agent init` would restore from the
  repository it cloned or linked. msagent took the clone or link back, and nothing was restored.

## Why this happens

`.mcs` is a cache that msagent writes from the cloud, and it must not come from the repository: a
cache from another clone or another environment would make msagent treat another Copilot Studio agent
as this project's. A `git add .`, or a commit made before AMS mode was on, can add it.

## How to fix it

Follow the message's hint. msagent never rewrites history itself.

- **Tracked:** run the `git rm -r --cached` command the message prints for each folder, which keeps
  your local cache, commit, and run the command again.
- **In commits:** remove the `.mcs` folders from the commits msagent would push, then run the command
  again. Where `git filter-repo` is installed, `git filter-repo --invert-paths --path-glob "*.mcs/*"`
  does it; otherwise squash those commits into one commit without them.
- **In the repository to restore:** run the `git rm -r` command the message prints for each folder,
  commit and push, then run `msagent agent init` again. The next deploy to Dev, `msagent agent deploy`,
  or `msagent agent deploy --remote` when the folder holds exactly the commit it deploys, connects the
  folder and rebuilds the cache.

## How to avoid it

Leave `.mcs` folders out of commits. The `.mcs/` line msagent adds to the project's `.gitignore`
keeps new ones out, and msagent's own commits leave out every `.mcs` folder.
