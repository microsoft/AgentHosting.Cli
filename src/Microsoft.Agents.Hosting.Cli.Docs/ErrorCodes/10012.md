# 10012: Workspace points to a different agent

[All error codes](../ErrorCodes.md)

## What happened

The workspace connection and the agent selected by the command do not identify the same agent.

## Why this happens

A pull selector may resolve to a different agent from the workspace's binding. During deployment or deletion, the bound cloud agent's schema name may differ from the schema this workspace is supposed to own. Continuing could overwrite or delete the wrong agent.

## How to fix it

- Compare the IDs and schema names printed in the error.
- For a pull, use the matching workspace or omit the selector to use that directory's own agent.
- If an unintended `--schema-name` caused the mismatch, remove it.
- For an incorrectly connected workspace, preserve local changes and obtain a fresh copy of the intended agent in a separate directory before continuing.

Do not edit hidden connection files or delete a cloud agent to bypass the identity check.

## How to avoid it

Keep one clear agent identity per workspace and verify deployment targets before write or delete operations.
