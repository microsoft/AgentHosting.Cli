# 17024: A referenced agent is absent from the destination

[All error codes](../ErrorCodes.md)

## What happened

A component refers to a connected or child agent that does not exist under that ID in the target environment.

## Why this happens

Connected and child agents are referenced by ID, and an ID exists only in the environment that issued it. Copying content to another environment does not automatically make those references valid.

## How to fix it

Inspect the connected-agent action and destination inventory. Deploy the referenced agent to the target environment first, and ensure the action uses the correct destination identity. Alternatively, remove the action if this deployment should not contain that dependency.

Inspect the destination before retrying: connectors, references, workflows, or prompts may have been processed before the component push failed. Their changes are not automatically rolled back.

## How to avoid it

Plan connected-agent deployment order and validate environment-specific references. Do not assume agent IDs can be reused unchanged when promoting content between environments.
