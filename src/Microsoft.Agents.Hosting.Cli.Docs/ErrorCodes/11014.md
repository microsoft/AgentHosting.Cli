# 11014: Workflow replacement lost the cloud copy

[All error codes](../ErrorCodes.md)

## What happened

The workflow no longer exists in the target environment. The local copy is unchanged.

## Why this happens

The environment refused an update, so the operation attempted to replace the workflow. Deleting the old cloud copy succeeded, but writing the replacement failed, and restoring the original cloud copy failed too. The error includes both write and restore failures.

## How to fix it

1. Preserve the local workflow files: they are the recovery source.
2. Resolve the reported service, connection, or permission problems.
3. Deploy again to recreate the workflow from the local copy.
4. Verify the recreated workflow and its connection readiness before relying on it.

Do not pull an absent cloud workflow over the local recovery copy, and do not delete local files to retry.

## How to avoid it

Keep versioned workflow backups and verify environment permissions and connections before updates that might require replacement.
