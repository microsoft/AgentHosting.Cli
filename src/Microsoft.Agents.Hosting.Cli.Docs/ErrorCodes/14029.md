# 14029: Deployment update timed out after submission

[All error codes](../ErrorCodes.md)

## What happened

The CLI attempted to update a deployment's Package Revision, but timed out before receiving the complete response. The deployment outcome is uncertain.

## Why this happens

The initial deployment read completed, and the subsequent update request was attempted. The service may still have accepted the new revision even though response handling exceeded the timeout. This is different from a timeout during the read before update.

## How to fix it

Do not immediately repeat the update. Preserve the client and any service request IDs and ask the service owner to inspect authoritative deployment state.

If the requested revision is already selected, another update may be unnecessary. If it was not applied and service health has recovered, repeat the intended package-revision update. Check that no other operator intentionally selected a different revision in the meantime.

Re-uploading the package does not resolve an uncertain deployment update.

## How to avoid it

Avoid concurrent deployment updates and check service health before changing a live deployment's revision.
