# 10018: Workspace belongs to another Dataverse organization

[All error codes](../ErrorCodes.md)

## What happened

The workspace's recorded Dataverse organization does not pass the check against the selected environment's organization.

## Why this happens

The connection may be stale, copied, or edited, or the command may target the wrong environment. The check also rejects a missing organization, a non-HTTPS address, embedded credentials, or a nondefault port. It protects operations from using an untrusted or mismatched organization.

## How to fix it

Compare the recorded organization and expected organization in the error.

- If the deployment selection is wrong, use a deployment naming the environment this workspace belongs to.
- If the connection is stale, preserve local edits and run `msagent agent pull` into a fresh directory for the intended agent and environment.

Do not hand-edit hidden connection metadata to make the addresses match.

## How to avoid it

Verify environment selections when reusing a workspace. Use separate working copies when that makes environment ownership clearer.
