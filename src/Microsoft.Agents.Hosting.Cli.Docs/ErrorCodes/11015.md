# 11015: Clone would replace unpublished workflow edits

[All error codes](../ErrorCodes.md)

## What happened

The clone destination already holds this workflow with local changes that the environment has not received.

## Why this happens

Cloning the cloud version into that project would overwrite unpublished edits. The CLI stops rather than silently discarding them.

## How to fix it

Choose one of these paths:

- Deploy the local changes first if they should become the cloud version.
- Clone into a different `--project` directory to inspect or use the cloud version without touching local work.
- If the edits are genuinely unwanted, preserve a backup and deliberately discard them through your normal source-control workflow before cloning again.

Do not delete the whole project or its registry just to clear this check.

## How to avoid it

Use fresh destinations for clones. Commit or back up workflow edits before operations that replace a working copy.
