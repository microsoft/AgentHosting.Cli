# 19013: The Copilot Studio agent is already held by another AMS agent

[All error codes](../ErrorCodes.md)

## What happened

The Agent Management Service refused to register the agent because another AMS agent already holds the Copilot Studio agent or cloud flow a deployment names. The message names that agent, and says when it is in another environment.

With AMS mode on, `msagent agent create` that clones a Copilot Studio agent or flow another AMS agent holds joins that agent instead. It fails with this error only when the join can't take the holder, before it asks or changes anything: the holder is homed in another environment, holds it other than through its Dev deployment, is still being registered or deleted, or its folder isn't on `main` yet. It also fails with it when another AMS agent came to hold the Copilot Studio agent or flow after msagent asked; msagent then takes back what it did.

## Why this happens

A Copilot Studio agent or cloud flow belongs to at most one AMS agent. The project may have been registered before, from another clone of its repository or by another user, or its folder was copied from another project. The record a local deploy sends to AMS fails the same way, as a warning, when another AMS agent holds the Copilot Studio agent the deploy wrote to.

## How to fix it

For `msagent agent create`, follow the message's remediation. A holder still being registered or deleted says so, and the remediation is to run the same command again once that finishes: it then joins the registered holder, or, once the holder is deleted, clones the agent as no AMS agent holds it. After a race, the remediation says to run the same command again, which joins that agent, and once a holder's owner pushes its folder to `main`, the same command joins it too. For a holder homed in another environment, or holding the agent other than through its Dev deployment, and for other commands, clone the repository of the agent that holds it and run `msagent agent init` in the clone, which restores and connects the agent, instead of registering a second agent. When the message says AMS kept a repository it created for this agent, pass that repository as `--repository-id` to use it.

## How to avoid it

Start work on a registered agent from a clone of its repository, or by cloning its Copilot Studio agent with `msagent agent create`, rather than from a copy of its folder.
