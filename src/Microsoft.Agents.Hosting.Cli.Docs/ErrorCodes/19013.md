# 19013: The Copilot Studio agent is already held by another AMS agent

[All error codes](../ErrorCodes.md)

## What happened

The Agent Management Service refused to register the agent because another AMS agent already holds the Copilot Studio agent or cloud flow a deployment names. The message names that agent, and says when it is in another environment.

## Why this happens

A Copilot Studio agent or cloud flow belongs to at most one AMS agent. The project may have been registered before, from another clone of its repository or by another user, or its folder was copied from another project. The record a local deploy sends to AMS fails the same way, as a warning, when another AMS agent holds the Copilot Studio agent the deploy wrote to.

## How to fix it

Clone the repository of the agent that holds it and run `msagent agent init` in the clone, instead of registering a second agent. When the message says AMS kept a repository it created for this agent, pass that repository as `--repository-id` to use it.

## How to avoid it

Start work on a registered agent from a clone of its repository rather than from a copy of its folder.
