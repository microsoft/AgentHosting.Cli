# 19008: The source kept changing in the repository

[All error codes](../ErrorCodes.md)

## What happened

The operation stopped because new commits changed the agent's source in its repository while it ran. A capture, and a remote deploy to Dev that first captures Dev's edits, say so in their own words:

- the capture of an MCS agent: `Nothing was captured: new commits kept arriving while the capture merged Dev's edits.`
- the capture of a standalone workflow: `Nothing was captured: the workflow changed in a commit after the one Dev runs, and a workflow capture doesn't merge.`
- the deploy of an MCS agent: `Nothing was deployed: new commits kept arriving while the deploy captured Dev's edits.`
- the deploy of a standalone workflow: `Nothing was deployed: the workflow changed in a commit after the one Dev runs, and a workflow capture doesn't merge, so Dev's edits weren't saved.`

## Why this happens

A capture merges Dev's edits with the newest commit of the repository's `main`, and gives up when new commits keep arriving through all its attempts. A standalone workflow's capture doesn't merge, so any commit after the one Dev runs stops it. A remote deploy to Dev captures Dev's edits the same way before it deploys, and gives up the same way.

## How to fix it

- For the capture of an MCS agent, capture again; it merges with the newest commit.
- For the capture of a standalone workflow, deploy the latest commit to Dev, which replaces Dev's edits, or make the same edits in your clone, then commit and push them.
- For the deploy of an MCS agent, deploy again; the capture merges with the newest commit.
- For the deploy of a standalone workflow, make the edits you want to keep in your clone, then commit and push them. Then deploy again with `--overwrite`, which replaces Dev's edits with the commit.
- Otherwise, run the command again; it takes the newest commit.

## How to avoid it

Coordinate pushes to an agent's folder and its collection folders with captures of the agent.
