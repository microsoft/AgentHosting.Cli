# 11001: Agent is not registered here

[All error codes](../ErrorCodes.md)

## What happened

The command could not find a managed-agent record matching your selection in this project, or, on an AMS route, no code agent of the home environment has the name given with `--agent-name` (error kind `agent-not-found`).

## Why this happens

The agent ID or name may be incorrect, the command may be using another project, or no agents may be registered yet. This lookup uses the local registry; it does not prove that the cloud agent is absent.

On an AMS route, the name is compared with the names of the home environment's code agents after both are trimmed and lower-cased (culture-invariant), so a different spelling or the wrong home environment (`--environment-id`, which defaults to the active environment) finds nothing.

## How to fix it

Run `msagent agent show` for the intended project to see its registered agents. Correct `--agent-id`, `--agent-name`, or `--project` as appropriate.

If an existing local Copilot Studio project has not been registered, use `msagent agent init`. Do not create another cloud agent just because a local selector did not match.

For an AMS code agent, run `msagent agent list --agent-type CodeAgent` to see the environment's code agents, or pass `--environment-id` with the agent's home environment. An `--agent-id` is used as given.

## How to avoid it

Use IDs from the project's current records and keep project paths explicit in automation. Keep configuration and workspace content together.
