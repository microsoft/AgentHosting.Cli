# 14035: Existing Azure bot could not be read

[All error codes](../ErrorCodes.md)

> [!IMPORTANT]
> **CodeAgent: future state - do not use.** This page preserves an implementation
> error contract, not supported public-preview provisioning instructions. Do not
> provision or enable the route to follow its recovery examples.

## What happened

CodeAgent deployment creation found the requested bot name unavailable, but could not read the bot at the intended Azure coordinates.

## Why this happens

When name availability says a bot already exists, create attempts to adopt it instead of provisioning another. That read may fail because of permissions, a service problem, incorrect subscription or resource group, or because the unavailable name belongs to a bot elsewhere. An unavailable name is not proof that the expected resource is accessible.

## How to fix it

Inspect the accompanying Azure error and verify the subscription, resource group, tenant, and bot name. Resolve the access or service problem before repeating the same create.

If the name belongs to an unrelated resource, choose an appropriate distinct deployment name rather than deleting that resource. Do not assume the CLI successfully adopted anything.

The CodeAgent create route requires `AzureBotServiceFeatures`.

## How to avoid it

Verify Azure coordinates and globally available bot names before provisioning, and retain the local record after successful creation.
