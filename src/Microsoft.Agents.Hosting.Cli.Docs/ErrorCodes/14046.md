# 14046: Boolean parameter value is invalid

[All error codes](../ErrorCodes.md)

## What happened

A provider or channel parameter declared as Boolean could not be interpreted as `true` or `false`.

## Why this happens

The CLI validates typed parameters against their definition. Values such as `yes`, `no`, `1`, and `0` are not accepted Boolean spellings. Validation can also reveal an incompatible Boolean default supplied by a provider catalogue.

## How to fix it

Change the named assignment to `true` or `false`, according to your intended setting. Letter case is accepted and normalized. For example, a channel setting can use `--parameters isEnabled=false` when disabling that channel is intentional.

If you did not supply the named value, inspect the live OAuth provider schema and report an invalid default to the service owner. Repeating an unchanged command will not fix a bad catalogue value.

## How to avoid it

Use explicit Boolean strings in scripts and configuration templates, and do not substitute numeric or conversational alternatives.
