# 16003: Azure provisioning context is ambiguous

[All error codes](../ErrorCodes.md)

> [!IMPORTANT]
> **CodeAgent: future state - do not use.** This page preserves an implementation
> error contract, not supported public-preview provisioning instructions. Do not
> provision or enable the route to follow its recovery examples.

## What happened

The CLI found multiple possible Azure subscriptions or resource groups and refused to select one automatically.

## Why this happens

CodeAgent deployment creation can infer a subscription or resource group only when there is exactly one available candidate. Gaining access to another subscription, or adding another resource group, can make a previously implicit choice ambiguous.

## How to fix it

Read which scope is ambiguous and repeat the original create with an explicit `--subscription <subscription-id>` or `--resource-group <name>`, or both. Verify that those coordinates and the tenant belong to the intended deployment.

This selection failure does not require deleting Azure resources or reducing your account's access. The direct-ARM CodeAgent route requires `AzureBotServiceFeatures`; consult `msagent deployment create --help` for its available options.

## How to avoid it

Provide explicit Azure coordinates in repeatable provisioning instructions instead of depending on the account having only one accessible scope.
