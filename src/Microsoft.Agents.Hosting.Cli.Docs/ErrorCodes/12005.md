# 12005: Authentication returned a different identity

[All error codes](../ErrorCodes.md)

## What happened

Interactive consent or a stored credential source returned an identity that did not match the captured authentication profile. The resulting token was rejected.

## Why this happens

A browser or operating-system account picker can remember a different identity. A configured or developer-pinned credential source can also return a different tenant or principal. The CLI refuses to use that result or silently fall back to another source.

## How to fix it

Use `msagent auth who` and `msagent auth status` to check the intended stored identity. For interactive consent, complete sign-in as that identity without changing accounts in the consent dialog.

For a stored or pinned credential source, correct its runtime configuration to match the intended tenant and principal before retrying. Do not bypass the mismatch by supplying tokens from another session or changing identities merely to avoid the error.

## How to avoid it

Check the account shown in each consent prompt, especially on machines with multiple work accounts or browser profiles. Keep the profile, configured source and sign-in identity aligned.
