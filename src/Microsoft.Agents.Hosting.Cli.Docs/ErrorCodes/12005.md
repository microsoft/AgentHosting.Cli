# 12005: Consent returned a different account

[All error codes](../ErrorCodes.md)

## What happened

Interactive consent completed with an account other than the CLI's active account. The resulting token was rejected.

## Why this happens

A browser or operating-system account picker can remember a different identity. Switching accounts during consent would otherwise let subsequent cloud changes run under an identity you did not select for the CLI.

## How to fix it

Run `msagent auth status` to check the active account. Run `msagent auth login` for the intended account, then repeat the original command without switching identities in the consent dialog.

If you really need another account, select it through the CLI's authentication commands first. Do not try to bypass the mismatch by supplying tokens from a different session.

## How to avoid it

Check the account shown in each consent prompt, especially on machines with multiple work accounts or browser profiles. Keep the CLI selection and interactive sign-in identity aligned.
