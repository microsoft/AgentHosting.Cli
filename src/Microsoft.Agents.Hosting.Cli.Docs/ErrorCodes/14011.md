# 14011: Publishing withheld after an incomplete push

[All error codes](../ErrorCodes.md)

## What happened

The MCS deployment saved draft content, but the CLI deliberately did not run the requested publish because parts of the push or workflow activation remained incomplete.

## Why this happens

Blocking warnings can include refused components, missing or disconnected component collections, and workflows that could not be activated. The deployment can be recorded even though these warnings make publishing unsafe. Unlike a publish failure, no publish was attempted here.

## How to fix it

Work through the specific warnings in the message. Restore missing collections and connect them to the intended environment where required. For refused flows caused by connection bindings, use `msagent deployment connection update` for the selected deployment and complete the required bindings.

Repeat the original deploy command with `--publish` after resolving every blocker. Do not publish an incomplete draft from the portal simply to bypass this guard.

## How to avoid it

Check collection availability and target connection readiness before requesting publication. Treat draft deployment and going live as separate outcomes.
