# 10022: Workspace files cannot be synchronized

[All error codes](../ErrorCodes.md)

## What happened

Workspace validation found files that the synchronization operation cannot read, or the agent's `settings.mcs.yml` (`agent.mcs.yml` for a classic agent without one) is empty, is not valid YAML, names no `schemaName`, or declares a `displayName` longer than the 42 characters Copilot Studio accepts when it creates or renames an agent, so the agent's identity cannot be read or used.

## Why this happens

Source files may contain malformed content, invalid structure, or unresolved merge conflict markers. The diagnostic summary identifies the affected files and positions where available. The problem is with readable workspace content, not necessarily authentication or the cloud service. A push, pull or deploy reads every agent's `settings.mcs.yml`, including a classic agent's, so an empty or malformed settings file stops the command instead of being skipped.

A deploy or push that would create the agent, or rename it, sends the `displayName` in `settings.mcs.yml` to Copilot Studio as the agent's name, counting any spaces around it, so a name of more than 42 characters stops the command before the agent is created or anything is pushed. An agent that already carries a longer name keeps it, and pushes as before.

## How to fix it

1. Open the files listed in the diagnostic summary.
2. Resolve conflict markers and repair the reported content or syntax. Restore a known-good version from source control if needed, preserving intentional local edits.
3. Rerun the original command after all listed problems are fixed.

Do not remove an entire workspace or reset its connection as a substitute for repairing the named files.

## How to avoid it

Resolve source-control conflicts fully before synchronizing. Review edits to structured workspace files and retain a recoverable version of working content.
