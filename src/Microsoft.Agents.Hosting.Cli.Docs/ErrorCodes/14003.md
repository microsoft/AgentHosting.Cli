# 14003: Existing target agent ownership is unverified

[All error codes](../ErrorCodes.md)

## What happened

An agent already uses the intended schema name in the target environment. The CLI stopped without pushing because the project cannot establish that this deployment owns it.

## Why this happens

When attaching or retargeting a workspace, the CLI looks up the schema name. Automatic adoption requires matching recorded ownership or deployment history. A matching name alone is not permission to replace another agent.

## How to fix it

Inspect the cloud agent ID and environment in the error. Confirm who owns the agent and preserve any cloud changes before proceeding.

Only if replacing that agent is intentional, repeat the MCS `msagent agent deploy` command with `--overwrite`. This accepts adoption and replacement; it is not merely a retry switch. Alternatively, use `--schema-name` with an appropriate name this project owns to deploy separately.

## How to avoid it

Retain project deployment records and use distinct schema names for unrelated agents. Review adoption carefully when moving between environments or restoring a project.
