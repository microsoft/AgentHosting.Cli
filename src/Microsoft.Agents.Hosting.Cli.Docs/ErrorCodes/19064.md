# 19064: AMS doesn't know which commit Dev holds

[All error codes](../ErrorCodes.md)

## What happened

`msagent agent capture`, or `msagent agent deploy --remote` to a Dev deployment without `--overwrite`, was refused because the Agent Management Service doesn't know which commit Dev's Copilot Studio agent or cloud flow holds. Nothing was captured or deployed.

## Why this happens

A capture merges Dev's edits with the commits made since the commit Dev holds, and a remote Dev deploy first captures Dev's edits the same way. AMS learns that commit from a remote deploy, a capture, or the record a local deploy with AMS mode on sends. Dev's agent or flow was last deployed while AMS mode was off, or by a deploy whose record AMS didn't get.

## How to fix it

Run `msagent agent deploy` to Dev from your clone, which records the commit Dev holds, then run the command again. A remote deploy with `--overwrite` replaces Dev's content instead, including any edits made in Copilot Studio.

## How to avoid it

Deploy to Dev with AMS mode on, that is, with `AmsMcsAgents` enabled.
