# 17025: The cloud agent changed while the push was prepared

[All error codes](../ErrorCodes.md)

## What happened

The component service rejected the push because the cloud agent changed after the workspace's synchronization baseline was obtained.

## Why this happens

Another author or process changed the agent in the cloud while the push was prepared. Cloud changes to components this push doesn't change are kept and the push is resent. The push stops when the cloud changed a component it also changes; with overwrite enabled, it replaces those components instead. It always stops, even with overwrite, when keeping the cloud changes would delete or replace knowledge files you changed locally, such as when the environment added a knowledge file with the same name as yours or deleted the agent or skill that holds it.

## How to fix it

Preserve local work, coordinate with other writers, then run `msagent agent pull`. Review the resulting content and any conflict diagnostics before deploying again. When the pull stops with [17035](17035.md), follow its guidance first.

Use the deployment command's `--overwrite` only when replacing cloud content is intentional. Without it, a dev deployment refuses components, connectors, prompts, and workflows that changed in the cloud; knowledge files are uploaded by design, and connector, prompt, and workflow changes may already have been written before this component rejection.

## How to avoid it

Avoid concurrent deployments and cloud edits. Pull near the start of an editing session and keep recoverable copies before intentional overwrites.
