# 17025: The cloud agent changed while the push was prepared

[All error codes](../ErrorCodes.md)

## What happened

The component service rejected the push because the cloud agent changed after the workspace's synchronization baseline was obtained.

## Why this happens

Another author or process changed a component this push also changes while the push was prepared. Cloud changes to other components are kept and the push is resent. With overwrite enabled, the push replaces the changed components instead of stopping.

## How to fix it

Preserve local work, coordinate with other writers, then run `msagent agent pull`. Review the resulting content and any conflict diagnostics before deploying again.

Use the deployment command's `--overwrite` only when replacing cloud content is intentional. Without it, a dev deployment refuses components, connectors, prompts, and workflows that changed in the cloud; knowledge files are uploaded by design, and connector, prompt, and workflow changes may already have been written before this component rejection.

## How to avoid it

Avoid concurrent deployments and cloud edits. Pull near the start of an editing session and keep recoverable copies before intentional overwrites.
