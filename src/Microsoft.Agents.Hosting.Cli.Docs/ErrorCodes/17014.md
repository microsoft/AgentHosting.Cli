# 17014: Agent attachment failed with no cloud agent left behind

[All error codes](../ErrorCodes.md)

## What happened

The workspace could not be attached by creating or adopting the named cloud agent. The failure check confirmed that nothing was left behind in the target environment.

## Why this happens

An underlying creation or attachment step failed. The original cause may involve permissions, service availability, or workspace setup; use the accompanying diagnostic rather than assuming every attachment failure has the same cause.

## How to fix it

Resolve the underlying failure, verify the intended environment and schema name, then rerun the original command. Preserve any local scaffold files that were already written and check the local directory before repeating setup.

This error differs from an uncertain attachment outcome: its cloud-state check succeeded. If another process has since created an agent with the same name, inspect current inventory before continuing.

## How to avoid it

Verify cloud access and local workspace permissions first. Avoid concurrent creation attempts for the same schema name.
