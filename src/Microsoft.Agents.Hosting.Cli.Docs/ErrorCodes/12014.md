# 12014: The token belongs to a different application

[All error codes](../ErrorCodes.md)

## What happened

The token identifies a client application other than the application the CLI expects.

## Why this happens

The token's application identity does not match the captured profile's required client ID.
An inconsistent public-client configuration, workload application or pinned Azure source can cause this.

## How to fix it

Check `auth who` and the captured application's approved configuration. For a workload, restore
that exact tenant/application credential or explicitly create the intended profile with
`--tenant` and `--applicationId`. For the public client, verify the build's approved configuration
(`21fadfba-178a-47f0-8ce6-07c05eb346ca` by default). Never substitute another source silently.

Do not use another product's application registration or copy tokens between tools. If the configured registration is correct and a fresh sign-in still fails, provide the non-secret application IDs and CLI version to support.

## How to avoid it

Keep the installed build and its approved application configuration together. Validate configuration when changing application registrations or distributing the CLI to another machine.
