# 12006: Required protected storage is unavailable

[All error codes](../ErrorCodes.md)

## What happened

The CLI cannot protect, read or persist required owned credentials/private caches, or its retained
token-cache backend is unavailable. It refuses a silent plaintext downgrade.

## Why this happens

Windows current-user DPAPI, macOS Keychain under the process-lifetime no-prompt policy, or Linux
GIO/D-Bus Secret Service may be unavailable, locked or inaccessible. Missing native prerequisites
and unsupported platforms also cause this. Storage initialization is lazy; metadata/help/repair
must not trigger unrelated identity or unlock UI.

## How to fix it

Restore the same user's platform storage access. On Linux ensure GIO and a usable session D-Bus
Secret Service are present and the collection is already unlocked. On macOS the CLI host must have
usable Keychain access under its explicit process-lifetime no-prompt policy. The CLI will not unlock
a store or change machine-wide policy. Check safe committed/cleanup guidance before retrying.

Linux owned-storage provider failures report a fixed category and storage operation (`read`,
`write`, or `clear`). A `step`, when available, names the connection or D-Bus call that failed,
such as `connect`, `read-alias`, `get-property`, `open-session`, or `get-secret`. These labels
do not include native error text, item identifiers, paths, or secret values. Validation after
a successful D-Bus call may report only the storage operation.

| Category | Recovery guidance |
| --- | --- |
| `service-unavailable` | Check the existing local session bus and Secret Service in the same execution user/session. |
| `store-locked`, `prompt-required` | Make the intended keyring accessible outside the CLI, using the session's keyring management tools. The CLI will not unlock it or invoke a prompt. |
| `native-library-unavailable`, `native-entry-point-unavailable` | Check architecture-matching GLib/GObject/GIO libraries (`libglib-2.0.so.0`, `libgobject-2.0.so.0`, `libgio-2.0.so.0`), version 2.36 or newer. Do not assume the daemon's availability proves the CLI can load its libraries. |
| `access-denied` | Check the execution user's native storage and session-bus access policy. |
| `malformed-response`, `native-object-not-found` | The adapter rejected a response or an expected native object disappeared. Report the category, operation, and step with the CLI version; do not assume the keyring is locked or delete its contents. |
| `native-failure`, `io-failure`, `cryptographic-failure`, `platform-not-supported` | Report the category, operation, step (if present), CLI version, OS, and architecture. The category alone does not establish a specific cause. |

For read-only Linux checks that neither read secrets nor activate/unlock the service:

```bash
busctl --user --auto-start=no call org.freedesktop.secrets /org/freedesktop/secrets org.freedesktop.Secret.Service ReadAlias s default
busctl --user --auto-start=no get-property org.freedesktop.secrets /org/freedesktop/secrets/aliases/default org.freedesktop.Secret.Collection Locked
```

An existing default collection and `b false` rule out a missing default collection and a
collection lock at the time of those checks, but not a CLI library, item, or protocol failure.
If `env list` fails here, subsequent agent commands can also report that no environment is
selected. Resolve the storage error, then run `msagent env list` and
`msagent env select <environment-id>`; do not silently select a different target.

The existing Linux token-cache-only baseline opt-in does **not** permit plaintext client secrets,
PFX passwords or other credential records and is not a remedy for this credential protection failure.
Do not delete shared broker/PAC/Azure state or source PFX files to fix owned storage.

## How to avoid it

Provision protected storage before authentication in the actual execution user/session. Native
OS/RID behavior requires separate platform validation; compilation and offline fakes do not prove it.
