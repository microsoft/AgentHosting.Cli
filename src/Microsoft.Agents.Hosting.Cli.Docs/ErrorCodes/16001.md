# 16001: Azure sign-in is required

[All error codes](../ErrorCodes.md)

## What happened

Provisioning does not have the Azure authentication it needs to continue.

## Why this happens

The operation needs a signed-in identity for the target Azure tenant. In a noninteractive run, it cannot rely on prompting you to sign in. A session for a different account or tenant is not a substitute for access to the requested subscription.

## How to fix it

Sign in through the CLI:

```text
msagent auth login
```

Use an account authorized for the intended tenant and subscription, then repeat the original operation. For automation, arrange the supported authentication setup before starting the provisioning command rather than placing passwords or bearer tokens in command arguments.

Do not change the subscription merely to avoid a sign-in failure.

## How to avoid it

Establish the intended account and tenant before provisioning. Check authentication separately from Azure permissions: successful sign-in alone does not grant permission to create or update resources.
