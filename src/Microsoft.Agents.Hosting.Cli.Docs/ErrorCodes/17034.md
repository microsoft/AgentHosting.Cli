# 17034: Shared environment variables would be overwritten

[All error codes](../ErrorCodes.md)

## What happened

The deploy stopped because it would have replaced the values of shared environment variables that the target environment already holds. The message names each variable's schema name and the environment, and the remediation names the files that change them.

## Why this happens

A shared environment variable is one the agent does not own, so other agents and flows in the environment may use it. The agent owns a variable only when the text before the first dot of the variable's schema name is exactly the agent's schema name, letter case included: for the agent `con_copy`, `con_copy.ApiKey` is its own, while `cr9_shared` and `con_copy_extra.ApiKey` are shared. The shared variable's file under `environmentvariables/` differs from what the environment holds: it was edited locally, it came from another environment, or `msagent agent copy` carried it over from the source agent. Replacing its value would change it for everything that uses it, so a deploy does not do it unless asked. Variables the agent owns deploy as usual.

## How to fix it

- To keep the environment's value, discard the local change to each named file: restore it from source control, or delete it when it came from another agent or environment. The agent then uses the value the environment holds.
- To replace the environment's value on purpose, re-run `msagent agent deploy` with `--overwrite`. In a dev deployment the same flag also overwrites cloud drift, so check what else it replaces first.

The deploy checks before it creates the agent or uploads anything for it, except for a classic-layout project with no cloud cache: that project's first deploy can check only after it has created the agent and uploaded its connectors, workflows, and prompts, and refuses before it pushes the components. Component collections the project declares are pushed before the agent, so they may already have been updated.

## How to avoid it

Edit a shared variable's file only when you mean to change its value for everything that uses it, and keep environment-specific values in each environment rather than in the workspace.
